=== GitHub Webhook Created or Configuration Changed

Detects creation or configuration change of a GitHub webhook. Attackers can add a hook to copy push, pull request, and workflow payloads (including secrets that land in those events) to an external URL.

==== Investigation guide



*Triage and analysis*



*Investigating GitHub Webhook Created or Configuration Changed*


`hook.create` adds a webhook. `hook.config_changed` updates the payload URL or other hook settings. Either action can send repository events to an attacker-controlled endpoint.


*Possible investigation steps*


- Identify `user.name`, `github.repo`, `github.actor_ip`, and `github.programmatic_access_type`.
- In repository Settings → Webhooks, inspect the payload URL, content type, and subscribed events. Treat unknown hosts as compromised.
- Pivot to `git.push`, `repo.download_zip`, and Actions secret creates by the same actor.


*False positive analysis*


- First-time install of Slack, Jira, or a deploy bot that registers a webhook.
- Terraform or GitHub App automation that manages hooks.


*Response and remediation*


- Delete unauthorized webhooks. Rotate secrets that may have been delivered in payloads.
- Revoke the actor's tokens if the hook was not approved.


==== Rule query


[source, js]
----------------------------------
from logs-github.audit-* metadata _id, _index, _version
| where
  data_stream.dataset == "github.audit"
    and (github.actor_is_bot is not null and github.actor_is_bot == false)
    and event.action in ("hook.create", "hook.config_changed")
| keep
    _id,
    _index,
    _version,
    @timestamp,
    event.action,
    user.name,
    github.org,
    github.repo,
    github.actor_ip,
    github.hashed_token,
    github.programmatic_access_type,
    github.user_agent,
    github.hook_id,
    github.name,
    github.actor_is_bot

----------------------------------
