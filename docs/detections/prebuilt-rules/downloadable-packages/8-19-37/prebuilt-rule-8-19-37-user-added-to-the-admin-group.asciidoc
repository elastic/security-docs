*Investigating User Added to the Admin Group*


Members of the macOS `admin` group can use `sudo`, install software, and change system-wide settings. Adversaries who gain a foothold may add an account they control to this group, using tools such as `dscl` or `dseditgroup`, to escalate privileges or keep privileged access. This rule uses Jamf Protect telemetry to alert when a user is added to the `admin` group.


*Possible investigation steps*


- Identify the account that was added to the `admin` group (`user.name`) and the account that performed the change (`process.user.name`), and confirm whether the change was requested or approved.
- Review the process that made the change (`process.executable`, for example `dscl`, `dseditgroup`, `sysadminctl`, or System Settings), its parent (`process.parent.executable`), and its responsible process (`process.responsible.executable`) to determine whether the change was interactive or scripted.
  - !{investigate{"label":"Show events having the same responsible process","providers":[[{"excluded":false,"field":"host.hostname","queryType":"phrase","value":"{{host.hostname}}","valueType":"string"},{"excluded":false,"field":"process.entity_id","queryType":"phrase","value":"{{process.responsible.entity_id}}","valueType":"string"}]]}}
  - !{investigate{"label":"Show events having the same parent process","providers":[[{"excluded":false,"field":"host.hostname","queryType":"phrase","value":"{{host.hostname}}","valueType":"string"},{"excluded":false,"field":"process.entity_id","queryType":"phrase","value":"{{process.parent.entity_id}}","valueType":"string"}]]}}
- Determine whether the added account was recently created, and whether it is hidden or has an unusual name or UID.
- Search the timeline for activity that followed the elevation, such as new persistence items (LaunchAgents, LaunchDaemons, login items), software installation, additional user creation, or security setting changes.
- Review authentication activity for the added account, including remote logins over SSH or Screen Sharing.
- Review other alerts for the same host to identify the initial access or execution activity that preceded the group change.


*False positive analysis*


- IT administrators, device management solutions, and privilege management tools legitimately add users to the `admin` group during provisioning or temporary elevation. Verify the change against change tickets or the expected management workflow.
- When the activity is confirmed benign, create an exception for the specific management process or service account rather than for the `admin` group.


*Response and remediation*


- Remove the account from the `admin` group if the change was not authorized.
- Disable or delete the account if it was created by the attacker, and reset the credentials of any compromised legitimate account.
- Review and revert changes made with the elevated privileges, such as persistence items, installed software, and modified security settings.
- Isolate the host if follow-on malicious activity is identified.
- Investigate how the attacker obtained the privileges required to modify group membership and remediate the initial access vector.
- Escalate to the incident response team and check other macOS hosts for similar group membership changes.


==== Setup



*Setup*


This rule requires data coming in from Jamf Protect.


*Jamf Protect Integration Setup*

Jamf Protect is integrated into the Elastic Agent using Fleet. Upon configuration, the integration allows the Elastic Agent to monitor events incoming events and send data to the Elastic.


*Prerequisite Requirements:*

- Fleet is required for Jamf Protect.
- To configure Fleet Server refer to the https://www.elastic.co/guide/en/fleet/current/fleet-server.html[documentation].


*The following steps should be executed in order to add the Jamf Protect integration:*

- Go to the Kibana home page and click "Add integrations".
- In the query bar, search for "Jamf Protect" and select the integration to see more details about it.
- Click "Add Jamf Protect".
- Configure the integration name.
- Click "Save and Continue".


==== Rule query


[source, js]
----------------------------------
configuration where host.os.type == "macos" and event.type == "change" and
  event.action == "od_group_add" and group.name:"admin"

----------------------------------
